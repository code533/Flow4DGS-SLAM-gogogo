# V3.2b — Real RAFT optical flow vs. GT rigid-flow and Jacobian sign diagnostic

**Goal:** determine why V3.2a's GT-relative pose analysis favors a different twist
composition/sign from the synthetic Jacobian test, without editing the SLAM
motion estimator or Tracking/Mapping. V3.2b is a **separate replay**, not an
offline evaluation of the earlier CSV and not a new ATE experiment.

## How it works

1. Read actual Bonn balloon2 images, depth, and world-to-camera ground-truth
   poses with the existing TUM/Bonn timestamp association (`TUMParser`).
2. Undistort RGB with the repository calibration. Bonn documents that depth
   is registered to its corresponding RGB image; therefore the diagnostic now
   remaps depth and dataset masks with the same rectification maps (nearest
   neighbor) by default so all pixel coordinates share the same grid. Use
   `--depth-grid legacy` only to reproduce the previous diagnostic, which
   undistorted RGB but left registered depth on the raw grid. Do not use the
   legacy-grid output to make a final geometric sign conclusion.
3. Run the repository RAFT checkpoint with **current RGB first, previous RGB
   second**, `iters=20`, and the exact InputPadder sequence used in
   `Camera.generate_flow`. `raw` is pixels; `tracking` is the effective
   flow after the original flow normalization followed by grid conversion,
   i.e. `raw * [(W-1)/W, (H-1)/H]`.
4. Back-project the **current depth**, transform current-camera 3D rays with
   `T_previous_w2c @ inv(T_current_w2c)`, project into the previous image and
   compute exact **current -> previous GT rigid flow**.
5. Reject missing depths / projections outside previous image. Separately
   check cross-frame depth consistency with a nearest-neighbor previous-depth
   sample; it is an **approximate occlusion gate**, not a semantic GT label.
6. Evaluate RAFT vs GT on all geometrically valid pixels, prior-static,
   prior-rejected and depth-consistent counterparts, reporting EPE and
   direction-angle / negative-cosine fractions. Angle statistics exclude flow
   vectors shorter than 0.3 px by default.
7. Compare first-order repository Jacobian predictions from `+xi_gt` and
   `-xi_gt` to exact finite-motion GT rigid flow. Optionally run the original
   parametric segmentation / static refit to compare estimated `+xi`/ `-xi`.
   GT is never involved in fitting.

## Usage

```bash
git fetch origin
git switch feature/cimd-real-flow-geometry-v32b
python -m unittest discover -s tests -p test_camera_motion_v32b.py -v

python scripts/analyze_camera_motion_v32b.py \
  --config configs/rgbd/bonn/ballon2.yaml \
  --inherit-from configs/rgbd/bonn/config.yaml \
  --start 1 --step 10 --count 40 \
  --yolo 1 \
  --depth-grid rectified \
  --output results/v32b_real_flow_rectified \
  --save-maps
```

Requires local Bonn balloon2 dataset, `pretrained/raft-things.pth`,
`pretrained/yolov9e-seg.pt`, CUDA/RAFT, PyTorch, NumPy, SciPy, OpenCV,
Pillow, YAML, trimesh and the repository's installed dependencies.

The earlier CSV produced before the depth-grid correction is a legacy-grid
diagnostic. Re-run into a new output directory (for example
`results/v32b_real_flow_rectified`) before interpreting flow polarity.

Use `--depth-grid legacy` to reproduce the old behavior for a controlled
comparison. Use `--yolo 0` for a faster **mask-ablation** replay without detector masks
(do not mix its results with the mask-enabled setting). To skip costly second
IRLS replay, supply `--skip-original-fit`, but note that residual-mask and
IRLS-sign metrics will then be absent.

## Outputs

- `<output>/v32b_per_frame.csv`: one row per checked frame, including pixel
  counts and prefix-qualified metrics such as
  `occlusion_static_raft_vs_gt_median_epe_px`,
  `occlusion_static_raft_vs_gt_negative_cosine_fraction`,
  `occlusion_static_jac_positive_vs_gt_mean_epe_px`,
  `occlusion_static_jac_negative_vs_gt_mean_epe_px`,
  `occlusion_residual_static_irls_positive_vs_gt_mean_epe_px`
  and corresponding negative-twist entries.
- `<output>/camera_motion_v32b_XXXXX.npz` (only with `--save-maps`):
  saved flow fields, projections masks, previous/current GT and GT twist.
- `<output>/failures.csv` if any frame could not be processed.

## Interpretation & limitations

- Strong correspondence of RAFT with **positive** GT rigid flow on trusted
  static/occlusion-consistent pixels supports the intended RAFT direction.
  Similarity to **negative** GT rigid flow suggests a sign or synchronization
  problem that should be checked independently.
- Jacobian is only first-order; exact finite-motion GT projection is the
  geometric reference. A small difference between Jacobian and exact GT flow
  does not by itself signal a bug.
- Semantics from YOLO are **prior masks**, not ground truth. Mask filenames
  follow `TUMParser` ordering. Additional residual masks are generated by
  replaying the original parametric segmentation rather than loading an
  unknown downstream mask.
- This replay uses `k_mad=5.0` for the optional parametric fit; if the
  active configuration uses a different `flow_cam_thres`, customize the
  diagnostic to match. This difference does not affect RAFT-vs-GT scoring.
- GT assumes the existing Bonn `TUMParser` pose association is correct.
  Check frame indices and timestamps when discussing large direction errors.
- The diagnostic rectifies depth and masks to the same pixel grid as RGB by
  default. The `legacy` mode intentionally retains the original loader's
  unremapped depth behavior and is not the preferred geometric reference.
- No ATE result is claimed. CPU test coverage is synthetic; the user must
  run CUDA/RAFT with real Bonn data.

Do **not** change the frontend's SE(3) sign or multiplication side solely
from these diagnostics. First compare the real-data RAFT/GT flow and verify
the pose conventions end to end.
