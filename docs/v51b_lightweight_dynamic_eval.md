# V5.1b — Lightweight dynamic reconstruction evaluation (Legacy vs Strict)

This branch adds **read-only, zero-extra-render** dynamic RGB-D scoring to
Flow4DGS' existing `eval_rendering()`. It DOES NOT alter Tracking, Mapping,
optical flow, Gaussian motion, YOLO, camera poses, or the V5.1a FOV policy.

## Scientific question

The five-run Balloon2 tracking-ATE averages were 0.04138 m (Legacy)
and 0.03658 m (Strict), an approximately 11.6% lower Strict mean, but
ATE alone does **not** demonstrate more accurate dynamic 3D geometry.
This experiment measures dynamic / boundary / interior RGB-D quality.

## What is scored?

For every frame from the existing **before_opt** final-map evaluation,
reuse its full-scene RGB, depth and opacity rasterization; no extra
rendering, point cloud copies, model fitting or independent YOLO pass.

Estimated dynamic ROI = `~motion_mask`, because this project's
dataset `motion_mask=True` means *static*. This is estimated
segmentation, not moving-object ground truth.

Disjoint regions:
- `all`: image-wide;
- `static`: estimated static pixels;
- `dynamic`: all estimated moving-object pixels;
- `interior`: dynamic ROI after eroding by 5 pixels;
- `boundary`: dynamic ROI minus interior.

The exact raw RGB and original raw depth observation provide masks.
Each region includes:
- RGB MAE on finite observed RGB pixels.
- RGB PSNR (dB), computed from per-pixel channel-mean MSE, finite
  capped at 120dB for exact-zero MSE.
- Depth MAE on ALL originally valid observed-depth pixels, with
  **0.5m fixed missing-prediction penalty** if the renderer depth is
  invalid or alpha <0.1 (candidate-independent denominator).
- Raw depth MAE on covered pixels, plus **coverage fraction** on all
  observed-depth pixels; do not interpret covered-only MAE without its
  coverage.
- RGB/depth pixel counts, segmentation hash, observed valid depth hash.
- Frame UID, dataset index and keyframe flag. Frame observations are
  evaluated at estimated camera poses, which can differ between runs.

**Not included:** actual ground-truth 3D flow, ground-truth dynamic
segmentation, true occlusion state, physically verified surface
correspondences, a dynamic-object 3D metric, or per-region SSIM.
Original `eval_rendering()` already handles *full-image* SSIM/LPIPS
and its main `final_result.json`; the lightweight addition should
not duplicate those costly evaluations.

## Run

```bash
git fetch origin
git switch feature/v51b-lightweight-dynamic-reconstruction-eval
git pull --ff-only

python -m unittest discover -s tests -p 'test_v51b_dynamic_eval.py' -v

python slam.py \
  --config configs/rgbd/bonn/v51b_balloon2_legacy.yaml \
  --eval --dynamic --exp_name=v51b_legacy_run1 --save_results=0

python slam.py \
  --config configs/rgbd/bonn/v51b_balloon2_strict.yaml \
  --eval --dynamic --exp_name=v51b_strict_run1 --save_results=0
```

**The lightweight metrics are produced automatically when existing
`Results.eval_rendering: true` runs**. Both configs are tiny: each
inherits its respective, otherwise identical, V5.1a config. Use
separate exp names, and ensure `before_opt` is enabled.

Output:
```
<run>/v51b_dynamic_eval/v51b_before_opt_per_frame.csv
```

This CSV is generated by the already-running *final before-opt*
rendering pass, for **each evaluated frame** (every_n_frame=1).
No full-resolution NPZ or PNG files are written by V5.1b.

The original `eval_rendering()` may still save existing PNGs when
`--interval` is supplied, and may render its existing novel-view
visualizations. Those are **legacy evaluation overhead**, not new
V5.1b work.

## Offline identical-frame / identical-mask comparison

```bash
python scripts/compare_v51b_dynamic.py \
  --legacy "<legacy run>/v51b_dynamic_eval/v51b_before_opt_per_frame.csv" \
  --strict "<strict run>/v51b_dynamic_eval/v51b_before_opt_per_frame.csv" \
  --output "results/bonn/v51b_matched_compare_run1"
```

Outputs:
- `v51b_matched_per_frame.csv`: Strict-minus-Legacy region metric
  changes, hashes, target counts and keyframe status for each frame.
- `v51b_comparison_summary.csv`: mean/median differences, frame
  counts and per-region comparison for all frames, 317–382 and 342–382.
- `v51b_comparison_report.md`: compact human-readable report.

**No silent mask mismatch or missing frame interpolation.**
The script requires the same frame indices, frame UIDs, region pixel
counts, dynamic mask SHA256 and valid-depth mask SHA256 on BOTH runs.
This catches inconsistent external segmentation, including stochastic
YOLO masks and data corruption. If the check fails, fix segmentation
consistency before drawing conclusions. An optional `--allow-partial`
only relaxes missing *frame IDs*, not mismatched target masks.
Both runs should use the same dataset, camera calibration, segmenter
and output stage.

The first experiment is a **mechanism smoke**, not proof. Once it works,
repeat with fixed seed pairs if feasible. Summary frame rows are
temporally correlated, so do not treat hundreds of frames as
independent experiment replications. Prefer comparing per-run means
over independent runs.

## Predeclared interpretation

A useful Strict-FOV signal requires lower **dynamic depth
penalized MAE**, lower dynamic RGB MAE / higher dynamic PSNR,
and no severe prediction coverage loss, especially around the
previously diagnosed FOV transition. If static/background metrics
improve but dynamic geometry worsens, ATE improvements alone
should not be described as 3D motion-accuracy improvements.

The 317–382 and 342–382 windows are **descriptive subsets** selected
from earlier V5.0–V5.1a observations, not clean held-out validation
periods. The current run evaluates the same training sequence on a
final fitted map (including interpolated deformation at non-keyframes),
so these are **in-sequence reconstruction metrics**, NOT independent
novel-time generalization.

A negative result is useful: visibility filtering might improve
tracking by suppressing bad motion while causing Gaussian lag for
unobserved objects. Only then should V5.2 introduce historical
motion prediction, with new future-frame verification.
